Laboratorio de caché

Ejecuta en vivo los métodos de la Cache Storage API que usa el service worker de Rodando UTP. Cada operación queda registrada en la bitácora con su resultado. caches es un objeto global: funciona desde el service worker y desde esta página.

Almacenamiento: caches.*

Lista las cachés del navegador (caches.keys()), crea una (caches.open()), consulta si existe (caches.has()) o la borra por completo (caches.delete()).

3

Operaciones de escritura y lectura

cache.add() y cache.addAll() descargan y guardan en un solo paso; cache.put() guarda una Response que tú construyes; cache.matchAll() devuelve todas las coincidencias.

Para probar la red de respaldo: pega una URL que no exista (por ejemplo img/no-existe.svg), ejecuta cache.add() y observa el error TypeError registrado en la bitácora: la caché solo guarda respuestas exitosas.

5

Qué está cacheando Rodando UTP

El service worker (sw.js) aplica una estrategia distinta según el recurso.

  • Precaching en install: caches.open() + cache.addAll() con la app estática (HTML, CSS, JS, iconos).
  • Estáticos y fuentes: network first con respaldo en caché; si falla la red, se sirve la copia guardada.
  • API pública (GET): network first; la respuesta se guarda con cache.put() y sin red se responde la última copia.
  • Sesión y reservas: nunca se cachean (datos personales y escrituras).
  • Limpieza en activate: caches.keys() + caches.delete() de las versiones anteriores.

Prueba el modo offline: en Chrome/Edge abre DevTools → pestaña Application → Service Workers → marca Offline (o DevTools → Network → Offline) y recarga: el sitio y esta página siguen respondiendo desde la caché.
